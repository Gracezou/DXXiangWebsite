### 部署形态说明：静态托管的三个连带约束

Q3 确认为静态托管（`nuxi generate` 预渲染全部页面为 HTML，部署到 CDN / 对象存储 / Nginx，**无 Node 运行时**）。这带来三处必须注意的约束：

1. **服务端重定向不生效**。`nuxt.config.ts` 的 `routeRules` redirect 依赖运行时，静态产物里没有进程去执行它。`/abort` → `/about` 的跳转须在托管层配置，见 B1-03。
2. **不能有服务端接口**。这正是联系表单被推到 v2.1 的原因——届时要么改混合渲染（表单接口单独走 server），要么接第三方表单服务。
3. **所有路由必须被预渲染出来**。i18n 的英文路由若无静态链接指向，爬取式预渲染可能漏掉，须显式声明，见 B3-02。

**B2 执行期发现**：

- [B2-03] **popperjs 补丁已确认不再需要**。build 脚本改为纯 `nuxi build` 后实测：`.output/server/node_modules/@sxzz/popperjs-es` 仍在原位（未被移到 `@popperjs/core`），但 `pnpm build` 退出码 0、`node .output/server/index.mjs` 启动正常、页面 200 且无运行时报错。该补丁是旧版 Element Plus SSR 的临时方案，升级后失效条件已不存在。

- [B2-05] **`.home_header` 不能放进 `el-container` 的直接子级**。初次实现把它作为 `el-container` 的子元素，导致 hydration node mismatch（服务端渲染出元素、客户端期望注释节点）。`el-container` 会按子节点类型推断布局方向，混入裸 `div` 会造成 SSR 与客户端的节点差异。已改为在 `el-container` 外层包一个 `.home_layout`，Header 置于 `el-container` 之外（它是 `fixed` 定位，本就不参与布局流）。修复后干净页面加载零警告零错误。

- [B2-08] **静态生成下 `routeRules` 的 redirect 会被编译成 `<meta http-equiv="refresh">` 页面**（`.output/public/abort/index.html`）。这是 Nitro 的行为，不是手写的——任务书禁止的是「手动用 meta refresh 冒充 301」。托管层配好 301 后，Nginx 会直接返回 301，根本不会读到该文件；若托管层漏配，它至少保证旧链接可达。**不要因为它存在就认为 301 已经完成。**

- [B2-08] **`404.html` 是 SPA 空壳**，不含 `error.vue` 的正文（实测正文只有站点 title）。静态托管下访客命中 404 时，错误页内容依赖客户端 JS 渲染，首屏会有短暂空白。属于可接受的标准行为，若要优化可在后续版本预渲染错误页。
