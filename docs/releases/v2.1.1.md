## 本版本的变更

### 修复 CI 无法构建

`pnpm/action-setup` 不允许 pnpm 版本有两处来源。`package.json` 已有 `packageManager: pnpm@10.34.5`，workflow 里又写了 `version: 10`，导致：

```
Error: Multiple versions of pnpm specified:
  - version 10 in the GitHub Action config with the key "version"
  - version pnpm@10.34.5 in the package.json with the key "packageManager"
```

Release 构建因此完全无法执行。已去掉 action 的 `version` 参数，由 `packageManager` 单一来源提供。

修复后按 CI 的方式在本地完整验证：`pnpm install --frozen-lockfile` 与 `pnpm generate` 均退出码 0，预渲染 110 条路由。

### 新增 Release 构建流水线

`.github/workflows/release.yml`：发布 Release 时自动构建静态产物并作为附件上传，同时支持手动触发。

产物打包为 `tar.gz` 并附 `sha256`。构建后有校验环节——检查 `index.html`/`_nuxt`/`404.html` 存在、页面数 ≥ 13、中英双语页面齐全，避免把残缺产物发出去。

### 新增部署配套

```
deploy/
├── nginx.conf      压缩、缓存、301、404、安全头
├── deploy.sh       构建 → 上传 → 原子切换 → 冒烟检查
├── rollback.sh     回滚到指定或上一版本
└── README.md       部署说明与上线前清单
```

缓存策略已逐条核对过产物中全部 157 个资源，无一遗漏：

| 路径 | 策略 |
| --- | --- |
| `_nuxt` / `_ipx` / `fonts` / `_i18n` | `immutable` 1 年（路径含内容哈希） |
| `images` / `favicon` | 30 天 |
| `*.html` 与 `*_payload.json` | 不缓存 |
| `sitemap` / `robots` / `style.xsl` | 1 小时 |

`_payload.json` 必须与 HTML 同策略——它是页面数据，缓存了旧版会与新 HTML 对不上。

部署脚本采用**软链原子切换**而非直接覆盖：rsync 覆盖线上目录时，传输过程中的访客会拿到新旧混合的资源（新 HTML 引用还没传完的 JS），软链切换没有这个窗口。冒烟检查中包含验证 `/abort` 确实返回 **301**。

## 与 v2.1.0 的关系
