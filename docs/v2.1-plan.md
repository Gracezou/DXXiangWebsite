## 批次 C1 — 依赖瘦身与框架升级

> **本批不改任何视觉**，是 C2 改版前的清场工作。三个孤儿依赖已在 v2.0 收尾时实测确认零使用。

### C1-01 移除 UnoCSS
- **依据**：v2.0 的 B4-02 重写 Header 后，全站唯一用过的 `flex-grow` 类名已被原生 flex 布局取代。实测全站无任何 UnoCSS 工具类。
- **要求**：卸载 `unocss` 与 `@unocss/nuxt`，删除 `uno.config.ts`，移除 `nuxt.config.ts` 中的模块注册。
- **验收**：`grep -rn "uno" nuxt.config.ts` 无结果；三断点视觉无变化。

### C1-02 移除 @vueuse/nuxt
- **依据**：v2.0 的 B2-04 删除 `window.onresize` 后，全站无任何 vueuse 组合式函数调用。
- **要求**：卸载依赖，移除模块注册与 `vueuse.ssrHandlers` 配置。

### C1-03 移除 @element-plus/icons-vue
- **依据**：v2.0 的 B4-06 重写 `Image.vue` 时错误占位图标已改为内联 SVG。
- **注意**：`element-plus` 本体在 C2-02 随轮播一并移除，本任务只处理图标包。

### C1-04 迁移到 Nuxt 4
- **背景**：当前 Nuxt 3.21.11。**放在改版之前**：迁移涉及 `app/` 目录结构调整，越晚做涉及的代码越多。
- **要求**：按官方迁移指南执行；`@nuxtjs/i18n` 需从 v9 升至 v10（v10 面向 Nuxt 4，注意其移除了 `bundle.optimizeTranslationDirective`）；同步核对 sitemap、robots、image 各模块的兼容版本。
- **验收**：预渲染路由数与 v2.0 一致（120 条）；中英双语全部页面正常。

**C1 验收**：三断点 × 双语走查**无任何视觉变化**；`pnpm generate` 成功。

## 批次 C2 — UI 风格改版（含 element-plus 彻底移除）

> **本批是 v2.1 的主体。** 改版与移除 element-plus 合并执行，因为二者是同一件事——去掉首页轮播即去掉最后一个 Element 组件。
> v2.0 的 B4-01 已建立设计令牌层作为地基，改版主要是替换令牌取值与调整版式结构，不需要回到各 `.vue` 里逐个查找。

### C2-01 扩展设计令牌
- **问题**：当前全站只有 `#003153` 一个品牌色，没有色阶也没有强调色，层级只能靠字号和留白撑，做不出重点。
- **要求**：在 `assets/scss/_tokens.scss` 中扩展色板：

  | 令牌 | 建议值 | 用途 |
  | --- | --- | --- |
  | `--dx-color-brand-deep` | `#001624` | 大面积深色背景 |
  | `--dx-color-brand` | `#003153` | **保留不变**，品牌锚点 |
  | `--dx-color-brand-mid` | `#0A5A8F` | 悬停、次级元素、边框 |
  | `--dx-color-accent` | `#00A8E8` | **新增**：CTA、链接、数据高亮、图标 |
  | `--dx-color-ai` | `#7C3AED` | **新增（克制使用）**：仅 AI 相关模块 |

- **字体**：英文可引入 Inter（**必须自托管 + 子集化，不得使用 Google Fonts CDN**），中文继续走系统字体栈——中文 web font 体积是 MB 级，不适合本站。
- **约束**：`--dx-color-ai` 只允许出现在 AI 赋能相关的元素上，不得扩散到全站，否则会稀释品牌色。
- **验收**：所有文字/背景组合对比度 ≥ 4.5（WCAG AA）；深色背景下的对比度需单独实测。

### C2-02 首页 Hero 重构（移除轮播与 element-plus）
- **背景**：三屏轮播是过时做法。实际问题有三个：用户绝大多数只看第一屏就滚走；三个并列标题等于**没有主张**；轮播抢走了本该给 CTA 的注意力。
- **要求**：
  1. 改为**单一静态 Hero**：一句明确价值主张 + 一个主 CTA + 一个次级入口
  2. 原三屏的标题与文案**下沉到服务板块**，作为并列卡片展示（那本就是它们该在的位置）
  3. 卸载 `element-plus` 与 `@element-plus/nuxt`，删除 `assets/scss/global.scss`（Element 主题变量）、`nuxt.config.ts` 中的 `elementPlus` 配置，以及 vite `additionalData` 中对 global.scss 的注入
  4. **Hero 文案不得新造业务承诺**，须由现有文案提炼，并随 C3-01 一并确认
- **性能目标**：首页 JS 传输量较 v2.0 的 **343 KB 下降 50% 以上**（主 chunk 320 KB 基本都是 element-plus），执行时记录实测值。
- **验收**：`grep -rn "element-plus" .` 除 lockfile 外无结果；首页 JS 实测值记入附录。

### C2-03 服务板块卡片化
- **当前问题**：全站是**居中短段落堆叠**，每句一个 `<p>`，读感像 PPT 不像网页；没有栅格与卡片，信息没有层级——「一站式需求解决」的三段话和「技术领先服务至上」的四段话视觉权重完全一样。
- **要求**：引入栅格与卡片建立层级；图文排布产生节奏变化，不再是清一色的等宽圆角矩形。**本任务只调整呈现结构，不改写文案内容**（文案变更集中在 C3-01）。
- **验收**：三断点 × 双语无破版；**英文版须单独走查**——英文字符数约为中文的 2.7 倍（v2.0 实测），是破版重灾区。

### C2-04 其余页面版式改版
- **范围**：关于、解决方案、联系我们、隐私政策四页，以及页头/页脚/错误页。
- **要求**：套用 C2-01 的令牌与 C2-03 的版式语言，保持全站一致。隐私政策是长文本页，重点是可读性（行宽、行高、段落间距）。

### C2-05 动效
- **要求**：加入克制的进场与 hover 动效。**必须尊重 `prefers-reduced-motion`**——该偏好开启时停止所有非必要动效。
- **验收**：开启系统「减少动态效果」后动效停止；性能不低于改版前。

**C2 验收**：三断点 × 双语全页走查；对比度全部达标；首页 JS 体积实测并记录；`pnpm generate` 成功。

## 批次 C3 — 内容更新（AI 赋能）

### C3-01 AI 赋能文案 ❓依赖 R1
- **已确认的信息架构**：AI **不是第四块独立业务**，而是贯穿现有三块业务的赋能层。因此不新增 solution 页的第四个 section，而是：
  1. **三块现有服务各补一个 AI 维度**的描述（技术解决方案 / 应用程序与网页 / 网络数据猎手）
  2. **首页增加一个横切板块**，说明 AI 能力如何贯穿各项服务
  3. Hero 的价值主张相应体现 AI 赋能
- **可写的能力范围**（项目方 2026-08-31 确认，**不得超出**）：
  - AI 应用开发
  - **基于商业模型做工程化**（非自研模型——文案不得暗示自研大模型）
  - AI 智能助手
- **硬约束**：
  - **不得编造模型名称、参数规模、准确率、性能指标、客户案例**
  - 不得使用「行业领先」「国内首创」「最先进」等无依据的表述
  - 客户是银行、证券、基金、保险、政府，**AI 领域的夸大表述在这些行业的合规风险高于一般行业**
  - 中英文各一套，纳入 i18n
- **交付方式**：agent 产出文案初稿 → **逐条提交项目方确认** → 确认后才写入语言文件。
- **验收**：文案全部落在上述三项能力范围内；无任何未经确认的数据或案例。

### C3-02 素材重新编排 ❓依赖 R2
- **已确认**：可复用的素材不更换，仅按新版式重新编排。

## 3. 已知的遗留风险

- **新加坡服务器 + 国内客户**：站点内容以中文为主，客户为国内银行、证券、基金、保险、移动、政府，办公地在青岛与杭州——访客主体在国内，但服务器在境外，跨境延迟约 60–100ms 且带宽有波动。静态站 + CDN 可缓解，**选 CDN 时需确认国内节点的回源优化**。建议上线后实测国内访问速度。

## 附录：执行期发现

> 格式：`- [任务ID] 发现内容 / 建议处理方式`。**只记录，不擅自处理。**

**C1 执行期发现**：

- [C1-04] **Nuxt 4 + i18n v10 下 `detectBrowserLanguage` 会造成 hydration mismatch**。预渲染的 HTML 对所有访客是同一份，cookie 驱动的客户端语言切换与服务端渲染内容不一致，控制台报 `Hydration completed but contains mismatches`，且访问 `/` 会渲染成英文。Nuxt 3 + i18n v9 下同样的配置被静默吞掉没有报错。**已关闭该功能**，语言完全由 URL 决定（`/` 中文、`/en` 英文），切换通过 Header 链接。这与 v2.0 任务书 B3-02 中「不要做同一 URL 按 cookie 切换语言」的要求一致。

- [C1-04] **`/en/abort` 产物消失**。i18n v10 不再为 `routeRules` 生成语言变体。影响可忽略——v1.0 只有中文站，`/en/abort` 这个路径从未存在过，本就不需要重定向。

- [C1-04] **Nuxt 4 默认把 CSS 内联进 HTML**。测量正文字数时若只剔除 `<script>` 不剔除 `<style>`，会把 CSS 算成正文（首页从 947 字虚增到 15719 字）。剔除两者后实测各页字数与 v2.0 基线一致（±20 字内）。CSS 内联对首屏性能是正向的，无需处理。

- [C1-04] **补齐了全部 14 张图片的 `width`/`height` 属性**。v2.0 的 B4-06 要求「所有图片声明 width/height 或 aspect-ratio 以消除 CLS」但未落实到位，图片未加载时渲染高度为 0。属于顺带修复的既有隐患，不是 Nuxt 4 引入的问题。

- [环境] **无头浏览器不触发原生 `loading="lazy"`**。实测所有 `eager` 图片正常加载、所有 `lazy` 图片一致失败，跨页面跨格式；手动改为 `eager` 后立即加载成功；`fetch` 同一 URL 返回 200。这是测试环境限制，不是代码缺陷——**不要为了让自动化测试通过而移除 lazy 属性**，那会牺牲真实用户的加载性能。验证产物完整性应改用 fetch 批量检查 URL 可达性（首页 70 个图片 URL 含全部 srcset 候选，全部 200）。**真实浏览器中的 lazy 行为需人工确认。**

**C2 执行期发现**：

- [C2-02] **移除 element-plus 的性能收益远小于任务书的估计，JS 未达「下降 50%」的验收目标**。实测首页 JS 从 v2.0 的 343 KB 降到 **307 KB，降幅仅 11%**。

  任务书原文写「主 chunk 320 KB 基本都是 element-plus」是**我的估计错误**。实际拆包分析：

  | chunk | 体积 | 内容 |
  | --- | --- | --- |
  | 主 chunk | 149 KB | Vue 3 + Nuxt 4 运行时 + vue-router（框架基线，不可削减） |
  | 次 chunk | 139 KB | **vue-i18n**（含 message compiler） |

## 批次 C7 — 视觉细节收尾

针对 C6 落地后复查出的四处问题。

### 已完成

- **氛围层修正**。旧版网格的实际可见度是「线的透明度 × 图层 opacity」的乘积：`0.09 × 0.5 = 0.045`，在深底上亮度差仅约 10/255，等于白做。现改为直接给足对比（0.13）并去掉外层 opacity 衰减，另加一层品牌蓝 + 微弱琥珀的径向光晕，让深底有纵深。

- **Hero 几何构成**。延续服务卡片的几何语言（三个节点对应三条业务线，连线指向中心），纯静态 SVG。**改了一次定位方案**：初版让它占据栅格右栏，结果中文标题被压成三行且断在「技术能/力」中间；改为绝对定位于文案区右侧后标题回到两行。注意必须相对 `.hero_inner`（文案区）而非 `.hero` 定位 —— 相对后者时垂直中心会落到事实条上，图形压住文字。

- **中西文空格**。修正 3 处：`构建先进的IT系统`（2 处）、`在App中使用网页` → 中西文之间补空格，符合中文技术写作规范。

- **英文标题行宽**。`13ch` 会把 `Technology that lands in real operations` 压成三行，放宽到 `20ch` 后为两行。

### 未采纳：入场动效与滚动显现

C2-05 曾承诺「克制的进场与 hover 动效」，本批实现后**又主动移除**，只保留 hover / focus 的 transition。原因是两次实测暴露了同一类风险：

1. **滚动显现依赖 IntersectionObserver，在本项目的自动化验证环境中完全不触发**。手动创建 fixed 定位、位于视口内的探针元素观察 1.5 秒，回调一次未触发 —— 与此前发现的「无头浏览器不触发原生 `loading="lazy"`」同源。**无法验证的特性不上线。**

2. **任何「从 opacity 0 淡入」的入场动画都有固有风险**：动画一旦未执行（浏览器对不可见页面的节流、CSS 未加载、动画被禁用），元素会永久停在透明状态，**内容彻底不可见**。实测中确实出现了全部 6 个元素 `opacity: 0` 的状态。尝试过 `animation-fill-mode: backwards` 的渐进增强写法，仍未能消除该风险。

   收益是一次性的淡入，代价是可能整屏空白 —— 这个交换不成立。

**已建立的验证方法**：注入 `*{animation:none !important;transition:none !important}` 模拟最恶劣情况，确认所有内容 `opacity` 仍为 1。这条检查应保留在后续任何动效改动的验收中。

`transition` 是安全的，因为它只在状态变化时生效，不影响元素的初始可见性 —— 卡片 hover、按钮、链接的过渡全部保留。
