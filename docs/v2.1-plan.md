## 0. 通用约定

沿用 v2.0 任务书第 0 节的全部约定，其中两条按项目方要求已调整：

1. **每个批次完成后提交一次**，commit 首行格式 `[批次ID] 简述`，正文按任务 ID 分条列出。
2. 每批结束必须验证：`pnpm lint`、`pnpm format:check`、`pnpm generate` 三项零报错，且中英双语 × 三断点（375 / 768 / 1440）人工走查通过。

## 批次 C1 — 依赖瘦身与性能

> 目标：把 v2.0 改造后遗留的孤儿依赖清掉，并解决最大的一块 JS 体积。
> **本批不改任何视觉**，是 C4 改版前的清场工作。

### C1-01 移除 UnoCSS（已确认零使用）
- **依据**：v2.0 的 B4-02 重写 Header 后，全站唯一使用过的 UnoCSS 类名 `flex-grow` 已被原生 flex 布局取代。实测全站无任何 UnoCSS 工具类。
- **要求**：卸载 `unocss` 与 `@unocss/nuxt`，删除 `uno.config.ts`，移除 `nuxt.config.ts` 中的模块注册。
- **验收**：`grep -rn "uno" nuxt.config.ts` 无结果；`pnpm generate` 成功；三断点视觉无变化。

### C1-02 移除 @vueuse/nuxt（已确认零使用）
- **依据**：v2.0 的 B2-04 删除 `window.onresize` 后，全站无任何 vueuse 组合式函数调用。
- **要求**：卸载依赖，移除 `nuxt.config.ts` 中的模块注册与 `vueuse.ssrHandlers` 配置。
- **验收**：同上。

### C1-03 移除 @element-plus/icons-vue（已确认零使用）
- **依据**：v2.0 的 B4-06 重写 `Image.vue` 时，错误占位图标已改为内联 SVG，不再引用图标包。
- **注意**：`nuxt.config.ts` 中 `elementPlus.icon: "ElIcon"` 是 `@element-plus/nuxt` 的配置项，与本包无关；若 C1-04 完成则一并删除。
- **验收**：依赖已卸载，`pnpm generate` 成功。

### C1-04 替换轮播组件，彻底移除 element-plus
- **背景**：这是 v2.1 **最大的性能收益点**。v2.0 结束时 element-plus 只剩 `ElCarousel` / `ElCarouselItem` 两个组件，但主 JS chunk 仍有 **320 KB**（首页 JS 合计 343 KB），大部分来自它。
- **要求**：
  1. 用轻量方案替换首页轮播 —— 优先评估自实现（本站轮播只需：三屏、自动播放、点击指示器、淡入/滑动切换），其次考虑 `embla-carousel`（约 5 KB）
  2. **必须保留的行为**：自动轮播、点击指示器切换、切换动画、`100dvh` 满屏高度、移动端文案居中
  3. **无障碍不得退化**：指示器需要可聚焦、有 `aria-label`；轮播容器加 `aria-roledescription="carousel"`；尊重 `prefers-reduced-motion`（该偏好开启时停止自动播放）
  4. 卸载 `element-plus`、`@element-plus/nuxt`，删除 `assets/scss/global.scss`（Element 主题变量）与 `nuxt.config.ts` 中的 `elementPlus` 配置及 vite 的 `additionalData` 中对 global.scss 的注入
- **验收**：首页 JS 传输量较 v2.0 的 343 KB **下降 50% 以上**（记录实测值）；轮播功能与 v2.0 一致；`grep -rn "element-plus" .` 除 lockfile 外无结果。

### C1-05 迁移到 Nuxt 4
- **背景**：当前 Nuxt 3.21.11，最新为 4.x。**放在 C1 末尾、C4 改版之前**：迁移涉及目录结构调整（`app/` 目录），越晚做涉及的代码越多。
- **要求**：按官方迁移指南执行；重点关注 i18n、sitemap、robots、image 各模块对 Nuxt 4 的兼容版本；`@nuxtjs/i18n` 需从 v9 升到 v10（v10 面向 Nuxt 4，并注意 v10 移除了 `bundle.optimizeTranslationDirective`）。
- **验收**：`pnpm generate` 预渲染路由数与 v2.0 一致；中英双语全部页面正常；lint 与 format 通过。

**C1 批次验收**：三断点 × 双语走查无视觉变化；首页 JS 体积实测并记录；`pnpm generate` 成功。

## 批次 C2 — 转化能力

> 目标：从「能被找到」到「能拿到线索」。这是 v2.1 的商业价值核心。

### C2-01 联系表单 ❓依赖 R4
- **背景**：v2.0 已加 CTA 按钮把流量导向联系页，但联系页目前仍只有静态联系方式，**没有任何留资入口**。
- **渲染模式影响**：站点当前是纯静态生成，没有服务端。三种落地方式，按 R4 的答案选择：

  | 方案 | 做法 | 代价 |
  | --- | --- | --- |
  | A. 混合渲染 | `routeRules` 让 `/api/contact` 走 server，其余保持预渲染 | 需要 Node 运行时的托管环境 |
  | B. 第三方表单服务 | 接入表单服务商的 endpoint | 数据经第三方，需评估合规 |
  | C. 邮件直发 | 表单提交到邮件服务 API | 需要 API Key，静态站无法安全存放 |

  **推荐 A**：可控、数据不外流；代价是托管环境要求提高。
- **要求**：
  1. 字段：姓名、公司、电话或邮箱（至少填一项）、需求描述；前端做必填与格式校验
  2. **必须做防滥用**：提交频率限制 + honeypot 蜜罐字段。**不要接入需要用户完成的验证码**
  3. 提交成功/失败均有明确反馈
  4. **表单收集个人信息，必须有隐私政策链接与同意勾选**
  5. 表单文案全部纳入 i18n（中英各一套）
- **验收**：本地提交测试能收到线索；蜜罐字段被填充时静默拒绝；未勾选同意时无法提交。

### C2-02 更换企业域名邮箱 ❓依赖 R5
- **现状**：`i18n/locales/*.json` 中仍是 `gracezou2829@gmail.com` / `galiathusi1i@gmail.com` 两个个人 Gmail。
- **要求**：替换为企业域名邮箱。**注意 vue-i18n 中 `@` 必须转义为 `{'@'}`**，否则构建失败（v2.0 踩过）。同时评估做邮箱混淆，降低被爬虫采集的概率。
- **验收**：中英语言文件中无 gmail.com；页面正常显示邮箱。

### C2-03 接入统计分析 ❓依赖 R6
- **要求**：按 R6 选型接入。**须遵守 Cookie 合规**，涉及非必要 Cookie 需有告知。
- **验收**：后台可见访问数据。

## 批次 C3 — 内容与运营

### C3-01 新闻 / 案例板块 ❓依赖 R7
- **背景**：**对企业站 SEO 而言这是长期自然流量的唯一来源**。当前站点是完全静态的 5 页，搜索引擎没有回访理由。
- **要求**：接入 `@nuxt/content`，建列表页与详情页，纳入 sitemap 与 i18n，加 Article 结构化数据。**本任务只交付框架，不编造案例内容** —— 首批内容由公司提供。
- **验收**：新增 Markdown 文件即可发布，无需改代码；列表与详情页中英双语可用。

- **要求**：提供地址后补充，并评估嵌入地图。**未提供则跳过，不得编造。**

## 批次 C4 — UI 风格改版

> **本批必须在 R1–R3 确认后才能开始。** 没有设计方向时 agent 自由发挥会产出不可控的结果。
> v2.0 的 B4-01 已建立设计令牌层作为地基：改版主要是替换 `assets/scss/_tokens.scss` 中的取值与调整版式结构，不需要回到各个 `.vue` 里逐个查找。

### C4-01 确定并落地视觉方向 ❓依赖 R1 R2
- **要求**：依据 R1 的参考与 R2 的主色决定，更新设计令牌（色板、字号阶梯、间距节奏、圆角）。**先只改令牌、不动结构**，产出一版全站预览供确认。
- **验收**：三断点 × 双语截图供人工确认；对比度仍满足 WCAG AA（≥ 4.5）。

### C4-02 排版结构改版
- **当前问题**（v2.0 未处理，属改版范畴）：
  - 全站是**居中短段落堆叠**，每句话一个 `<p>`，读感像 PPT 不像网页
  - 没有栅格与卡片，信息没有层级 —— 「一站式需求解决」的三段话和「技术领先服务至上」的四段话视觉权重完全一样
  - 图片全是等宽圆角矩形，从头到尾一个节奏
- **要求**：引入栅格与卡片，建立信息层级，图文排布产生节奏变化。**文案内容不得改写**（只调整呈现结构），如需改文案单独提出。
- **验收**：三断点 × 双语无破版；英文版需单独走查（英文字符数约为中文的 2.7 倍）。

### C4-03 动效与图片素材 ❓依赖 R3
- **要求**：加入克制的进场与 hover 动效；**必须尊重 `prefers-reduced-motion`**。R3 确认更换素材则一并替换，新图需保持 `@nuxt/image` 的 WebP 与响应式处理，并补 i18n 的 `alt.*` 文案。
- **验收**：开启「减少动态效果」系统偏好时动效停止；Lighthouse 性能不低于改版前。

## 批次 C5 — 上线准备

> **本批在全部改造完成后执行**，是正式上线的最后一道。

### C5-01 填入 ICP 备案号
- 填 `app.config.ts` 的 `site.icp`（留空时页脚不渲染该行，填入即生效）。若有公安备案号一并填 `site.police`。
- **验收**：页脚展示备案号，链接跳转工信部备案系统正常。

### C5-02 开放搜索引擎抓取
- `nuxt.config.ts` 的 `robots` 从 `Disallow: /` 改为允许抓取。**必须在备案通过之后**。
- **验收**：产物 `robots.txt` 允许抓取且声明了 sitemap 地址。

### C5-03 托管层配置
- 配置 `/abort` → `/about` 的 **301**（静态产物本身不含真正的 301，README 有 Nginx 示例）。
- 404 已由项目内 catch-all 路由兜底，托管层配置为可选增强。
- **验收**：线上访问 `/abort` 返回 301 而非 200。

### C5-04 Lighthouse 实测（项目方已确认放在最后统一执行）
- 中英文首页 + 一个内页，桌面与移动端各跑一次。
- **验收目标**：Performance ≥ 85、Accessibility ≥ 90、Best Practices ≥ 90、SEO ≥ 90。未达标项记录并评估。

### C5-05 暗色主题（可选）❓依赖 R9
- v2.0 的 B2-06 已移除未使用的 `@nuxtjs/color-mode`。若需要则重新引入并**完整实现**全站暗色样式，依托 C4-01 的令牌。
- **验收**：跟随系统偏好切换，两种模式下全站可读、对比度均达标。

## 2. 建议执行顺序与理由

```
C1 依赖瘦身  →  C4 UI 改版  →  C2 转化能力  →  C3 内容运营  →  C5 上线准备
（清场，无视觉变化）  （需 R1-R3）    （需 R4-R6）    （需 R7-R8）   （最后统一做）
```

- **C1 必须最先**：孤儿依赖清掉后代码更简单，Nuxt 4 迁移越早涉及的代码越少，改版时也不必再兼顾 Element Plus 的样式覆盖。
- **C4 建议排在 C2/C3 之前**：表单与案例页都要套用新的视觉，先改版可以避免这两块做两遍。
- **C5 必须最后**：开放抓取和 Lighthouse 都应该基于最终形态。

如果希望**尽快拿到线索**而非尽快改版，可以把 C2-01 表单提到 C1 之后先做，代价是改版时表单样式要重做一次。
